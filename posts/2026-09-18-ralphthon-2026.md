## 왜 (문제·동기)

2026년 9월 18일, 부산에서 열린 랄프톤에 다녀왔다. 이름은 심슨의 랄프 위검에서 온 "Ralph Wiggum Loop"에서 땄다. 바보 같은 짓을 반복하면서 조금씩 나아지는 캐릭터처럼, 같은 프롬프트를 에이전트에게 계속 다시 넣는 루프다. 10시부터 오후 5시까지 하루짜리였다.

규칙이 특이했다. 사람은 설계와 명세만 한다. 에이전트에게 한 번 던지고 나면 손을 뗀다. 팀마다 노트북 두 대가 필요한데, 하나는 에이전트 실행용이고 하나는 관전용이다. 실행용 노트북은 디스코드에 화면을 공유한 채 에이전트룸에 들어간다. 15시에 에이전트룸이 열리면 실행은 끝이다. 5분 동안 돌아가는지 확인만 하고, 그 5분은 녹화돼 심사위원에게 간다. 이후 사람의 수정은 없다.

그리고 점수. 자율수행 점수는 모든 팀이 25점에서 시작하고, <mark>**사람이 개입할 때마다 1점씩 깎인다.**</mark> 에이전트가 멈추거나 뭘 물어보면 사람이 들어가 고쳐야 하고, 그때마다 점수가 나간다.

주제는 "여행". 여행지 추천이나 티켓팅 같은 흔한 서비스 말고 기발한 걸 만들라는 조건이 붙었다.

## 어떻게 (과정)

### 오전: 강의, 회의, 그리고 문서

![랄프톤 하루 — 사람이 일한 시간과 에이전트가 일한 시간](/images/ralphthon-2026/01-timeline.svg)

오전 강의의 키워드는 "AI에게 코딩만 시키지 말고 완주 구조를 설계하라"였다. 원형 랄프 루프는 `while … do agent prompt.md; done` 한 줄이다. 루프에는 다섯 요소가 있다고 했다. 목표(Goal), 멈춤 조건(Stop condition), 하네스, 피드백, 상태. 강사의 경험담이 인상적이었다. "이 프로젝트 완성해줘"라고 골을 잡았더니 에이전트가 48시간을 돌면서 플랜 한도를 다 쓰고도 도달률이 0%였다고.

11시 58분에 아이디어를 정했다. 팀원이 낸 안이었다. 포항에 가면 다들 호미곶 손 조각상만 찍는다. 예쁘지도 않은데 정보가 거기밖에 없어서다. 사진 찍기 좋은 곳 정보는 인스타·페북·구글에 흩어져 있어서 결국 늘 가던 곳만 간다. 그래서 이미 찍은 사진을 올리면 사진 속 EXIF 위치로 지도에 핀이 자동으로 찍히고, 유명 스팟을 누르면 그 옆 숨은 스팟이 "여기 말고 여기"로 뜨는 국내 사진 스팟 지도를 만들기로 했다. 이름은 샤츠(Schatz). 첫 화면 문구는 "유명한 데 말고, 여기도 예뻐요."

주최 측이 예시로 든 두 서비스(사진 점수 경쟁, 실시간 "별로다" 지도)와 재료가 겹쳐서, 다른 점을 PRD 첫머리에 못 박았다. 점수도 경쟁도 없고, "별로다"가 아니라 "여기도 예쁘다"이고, 데이터는 코멘트가 아니라 사진의 EXIF다.

### 사람이 쓴 건 문서 여섯 장, 앱 코드는 0줄

12시 16분부터 51분까지 하네스를 만들었다. 앱 코드는 0줄, 사람이 쓴 건 여섯 장이다.

- **PRD.md** — 문제, 범위, 5분 시연 대본, 완료 조건 AC0~AC9.
- **PLAN.md** — M0 하네스 → M1 지도 → M2 여기 말고 여기 → M3 업로드 → M4 마감. 체크박스 23칸.
- **AGENTS.md** — 매 반복의 시작 절차, 변경 금지 목록, 그리고 "사람은 없다. 묻지 말고 결정하라."
- **PROMPT.md** — 에이전트를 부를 때 들려 보내는 한 장. 마감용 PROMPT-FINAL.md 하나 더.
- **tests/smoke.spec.js** — Playwright 테스트 10개. 사람이 미리 쓰고 에이전트는 수정 금지.
- **ralph.sh** — 루프 스크립트.

발표 대본의 한 문장 요약이 "멈출 줄 아는 랄프 루프"였을 만큼, 설계의 중심은 멈추는 조건이었다.

![멈출 줄 아는 랄프 루프 — 한 바퀴와 멈추는 조건](/images/ralphthon-2026/02-loop.svg)

ralph.sh는 PROMPT.md 한 장을 들고 Claude Code를 부른다. 에이전트는 규칙과 PRD와 PLAN을 읽고, git log와 테스트로 현재 상태를 본 다음, PLAN의 첫 미완 항목 하나를 만든다. 검증을 통과하면 체크하고 진행 로그에 한 줄 적고 커밋한다. 23칸이 다 체크되고 테스트 10개가 다 통과하면 DONE 파일을 쓰고 나간다. 스크립트는 에이전트가 나올 때마다 DONE이 있는지 본다. 있으면 끝, 없으면 5초 뒤 같은 프롬프트로 다시 부른다. 최대 10번. 14시 30분부터는 "새 기능 금지, 정리와 커밋만"인 마감 프롬프트로 바꾸고, 14시 48분에는 강제 종료한다.

<mark>**상태를 에이전트 머릿속이 아니라 파일과 git에 둔 게 핵심이었다.**</mark> PLAN.md 체크박스와 커밋이 상태라서, 에이전트가 중간에 죽거나 "다 됐다"고 착각하고 나가도 다음 반복이 파일을 읽고 끊긴 자리부터 이어간다. 사람이 다시 칠 일이 없으니 개입이 0회가 된다.

거짓 완료도 막아야 했다. 완료 조건이 곧 멈춤 조건이라, 에이전트가 테스트를 약화시키면 루프가 거짓으로 끝난다. 그래서 <mark>테스트 파일은 사람이 미리 쓰고 변경 금지 목록에 넣었다.</mark> 못 박은 게 더 있다. 서버 없이 정적 파일로, file://로 열려야 하고, 지도 라이브러리는 로컬에 복사하고 외부 요청은 지도 타일 하나만. 빌드 실패로 두 시간을 날리는 게 제일 흔한 실패 패턴이라서다.

작은 함정도 미리 밟았다. 드라이런에서 첫 ralph.sh가 DONE으로 끝난 뒤에도 마감 정리를 돌려 DONE까지 치워 버리는 버그가 나와서, 시간 종료일 때만 정리하도록 고쳤다. 노트북에 GPS가 든 사진이 한 장도 없어서 시드 사진에는 좌표를 EXIF로 심었다. 개인 설정도 격리했다. 평소 쓰는 Claude Code 설정의 훅과 스킬이 자율 실행 중에 질문을 유도할 수 있어서, 자격증명과 모델만 든 별도 설정 폴더로 돌렸다.

### 13:02, 엔터

13시 2분에 start.sh를 쳤다. 창이 좌우로 갈라져 왼쪽이 에이전트, 오른쪽이 관전이었고, 그 뒤로는 아무것도 하지 않았다.

## 결과

<mark>**13시 2분 시작, 13시 18분 DONE. 반복 1회, 16분, 개입 0회.**</mark>

에이전트는 M0부터 M4까지 순서대로 커밋 6개를 남겼다. 도구 설치와 시드 빌드, 지도와 핀, 근처 숨은 스팟 목록과 상세, 사진 업로드와 저장, 마지막으로 외부 요청 감사와 README 갱신. PLAN 23칸 전부 체크, 테스트 10개 전부 통과. 스크립트가 준비해 둔 재호출·마감 프롬프트·강제 종료는 하나도 발동하지 않았다.

만들어진 건 이렇다. 대한민국 지도, 유명 스팟 25곳이 붉은 핀, 시드 사진 6장이 초록 핀. 지역 칩 「제주」를 누르면 제주로 날아가고, 유명 스팟 「성산일출봉」을 누르면 하단에 「여기 말고 여기 · 3곳」이 0.4km부터 거리순으로 뜬다. 「내 사진 올리기」로 사진을 넣으면 EXIF 위치에 핀이 떨어지고, 새로고침해도 남아 있다. GPS 없는 사진이면 지도를 탭한 자리에 핀이 박힌다.

15시에 에이전트룸이 열렸고, 결과물은 5분 동안 그대로 돌아갔다. 발표 대본에서는 루프를 "에이전트를 자동으로 다시 출근시키는 장치"라고 풀었다.

재밌는 흔적도 있었다. 에이전트가 진행 로그와 DONE 파일에 적은 시각은 13:08부터 13:38까지인데, 실제 커밋 시각은 13:03부터 13:18까지다. 뒤로 갈수록 벌어져 마지막엔 20분 차이가 났다. 규칙은 반복 시작 때 `date`를 한 번 치는 것이었고, 항목별 시각은 에이전트가 스스로 적은 값이라 git과 맞지 않았다. <mark>에이전트가 적는 숫자보다 git이 찍는 숫자를 믿어야 한다</mark>는 걸 로그가 보여 줬다.

## 배운 점

<mark>**루프는 잘될 때가 아니라 잘못될 때를 위한 보험이다.**</mark> 한 바퀴에 끝났으니 루프가 무의미했냐고 하면 아니다. 에이전트가 중간에 나가떨어져도 사람 없이 재기동되는 구조가 있었기 때문에 손을 뗄 수 있었다.

<mark>**완료 조건을 에이전트가 못 건드리게 하는 게 하네스의 절반이다.**</mark> 테스트를 사람이 쓰고 잠그지 않았다면, 16분 만의 DONE을 믿을 수 없었을 것이다. 다음에도 "무엇을 만들지"보다 "무엇이 되면 끝인지"를 먼저 쓰고 잠글 것이다.

강의에서는 두 시간의 대부분이 문서 읽기라고 했다. 실제로 하네스를 쓴 뒤 엔터를 치기 전까지는 PRD와 PLAN과 AGENTS를 읽고 의도와 다른 줄을 고치는 시간이었다. 에이전트가 초안을 써 줘도 그 단계는 사람이 한다. 코드를 안 쓴 날이었는데, 평소보다 더 설계자였다.
